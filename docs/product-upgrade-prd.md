# 产品需求文档：灵感来袭公开 Beta 全面升级

**版本**：1.0<br>
**日期**：2026-08-06<br>
**目标版本**：2.0.0-beta.1<br>
**需求质量评分**：94/100

---

## 1. 执行摘要

“灵感来袭”将从面向作者个人工作流的链接收藏看板，升级为面向技术研究者的本地优先“稍后研究”工作台。产品帮助用户把 GitHub 仓库、文章、视频和工具链接快速收进统一入口，经过整理、阅读、记录和结论沉淀，转化为可复用的本地研究资产。

本轮目标不是扩张更多内容平台、团队协作或云同步，而是达到可公开推广的 Beta 标准：Windows 用户可以低门槛启动；现有 `DATA.md`、笔记、截图和正文可以无损迁移；本地数据接口不会因消息入口或公网隧道意外暴露；核心收藏与研究流程具备可验证的数据可靠性。

## 2. 产品定位

### 2.1 一句话定位

把散落的技术链接，变成可执行、可追踪、可沉淀的本地研究成果。

### 2.2 核心用户

**主要用户：技术研究者**

- 开发者、独立创作者、产品经理、技术内容作者。
- 经常收藏 GitHub 项目、技术文章、教程和视频。
- 收藏量大，但缺少整理、回顾和形成结论的流程。
- 重视隐私、可迁移性和对本地数据的控制权。

**次要用户：重度信息收集者**

- 愿意安装本地工具，但不一定熟悉 Node.js。
- 需要更简单的安装、导入、搜索和模板化记录体验。

### 2.3 核心工作流

```text
发现链接 → 收进“收件箱” → 自动补全元数据/建议分类
→ 决定是否研究 → 阅读正文/记录笔记/形成结论
→ 完成或归档 → 可搜索、可导出、可恢复
```

## 3. 问题陈述

### 3.1 当前问题

1. 产品同时表达“待办、收藏、研究、软件评测”四种心智，主价值不够聚焦。
2. 固定八分类和软件安装型档案不适用于所有研究内容。
3. 分类编号兼作持久主键，删除后可能复用并关联旧档案。
4. 多入口并发写入缺少串行化和重复 URL 处理。
5. 企业微信公网穿透可能暴露未认证的数据接口。
6. 首次使用、静态演示、`DATA.md` 文案和故障反馈不一致。
7. 安装依赖 Node.js 和命令行，对公开推广形成门槛。
8. 测试以模块测试为主，缺少 API、迁移、浏览器主路径和分发验证。

### 3.2 期望结果

- 用户在首次启动后 5 分钟内完成第一条收藏。
- 任意写入、删除、迁移和恢复操作不造成数据串档或静默丢失。
- 外部消息入口不要求暴露完整数据服务。
- 不同内容类型可以使用合适的研究模板。
- Windows 用户不需要理解项目目录和环境变量即可完成基础使用。

## 4. 成功指标

### 4.1 Beta 发布门禁

| 指标 | 目标 | 验证方式 |
| --- | --- | --- |
| 首次收藏完成时间 | 新用户中位数 ≤ 5 分钟 | 5-10 名目标用户可用性测试 |
| 核心解析成功率 | 常用样本直接成功率 ≥ 85%，保存成功率 ≥ 99% | 固定回归 URL 集合 |
| 数据迁移 | 现有样本 100% 保留条目、笔记、截图和正文 | 迁移夹具前后校验 |
| 数据可靠性 | 阻断级数据丢失缺陷为 0 | 并发、崩溃、恢复和回滚测试 |
| 安全 | 公网入口无法匿名读取或修改本地数据 | API 安全回归测试 |
| 核心流程 | 收藏、编辑、研究、归档、恢复全部通过 | 浏览器端到端测试 |
| Windows 启动 | 全新 Windows 环境一条路径启动成功 | 干净虚拟机验证 |

### 4.2 公开 Beta 观察指标

- 7 天内再次使用率。
- 收藏后 7 天内进入“研究中”的比例。
- 收藏后形成有效笔记或结论的比例。
- 解析兜底率、写入失败率和恢复使用率。
- 浏览器入口、手工粘贴、企业微信/钉钉入口的使用占比。

指标采集默认关闭。公开 Beta 阶段优先使用可用性测试、匿名问卷和用户主动提交的诊断包；若增加遥测，必须单独征得用户同意。

## 5. 用户故事与验收标准

### 5.1 首次使用

**作为**第一次安装的技术研究者，<br>
**我希望**启动后直接看到示例和明确的第一步，<br>
**从而**无需阅读长文档即可保存第一条链接。

- [x] Windows 推荐入口无需手工配置环境变量。
- [x] 缺少依赖、端口占用或目录不可写时给出可执行的错误提示。
- [x] 空数据页的“新增第一条”可直接进入收藏流程。
- [x] 所有界面统一使用“数据文件”或 `DATA.md`，不再误称 README。

### 5.2 安全收藏

**作为**使用浏览器或消息入口收藏链接的用户，<br>
**我希望**只有经过授权的入口可以写入数据，<br>
**从而**不会因公网穿透泄露或破坏本地研究库。

- [x] 非本机请求必须通过明确的访问令牌或受限回调入口。
- [x] 企业微信和钉钉只能调用“收集链接”能力，不能访问普通数据接口。
- [x] 写接口具备请求体上限、基本速率限制和审计日志。
- [x] 文档准确说明哪些数据留在本机、哪些请求会访问第三方。

### 5.3 数据迁移与恢复

**作为**现有用户，<br>
**我希望**升级后原有条目和研究档案继续可用，<br>
**从而**可以放心升级而不必重新整理资料。

- [x] 升级前自动生成完整、可识别版本的备份。
- [x] 迁移为每个条目分配不可复用的稳定标识。
- [x] 迁移失败时不覆盖源数据，并能显示失败原因。
- [x] 用户可以回滚到迁移前数据。
- [x] 删除条目进入回收站，不立即删除研究档案。

### 5.4 研究模板

**作为**研究文章、视频、仓库或软件的用户，<br>
**我希望**选择适合内容的记录模板，<br>
**从而**不用在无关字段中填写信息。

- [x] 提供通用研究、文章阅读、视频学习、项目调研、软件评测模板。
- [x] 模板字段保存为向后兼容的结构化 Markdown。
- [x] 用户可以切换模板，已有内容不会静默丢失。
- [x] 通用模板至少包含“为什么收藏、关键发现、行动项、结论”。

### 5.5 整理与检索

**作为**拥有大量收藏的用户，<br>
**我希望**使用收件箱、自定义分类、标签和全文检索，<br>
**从而**在需要时快速找到曾经研究过的内容。

- [x] 新收藏默认可以进入收件箱，自动分类仅作为建议。
- [x] 支持自定义分类和多标签。
- [x] 搜索覆盖标题、摘要、标签、研究笔记和已抓取正文。
- [x] 重复 URL 保存时提示已有条目，并允许打开、合并标签与收藏原因或仍然保存。

## 6. 功能范围

### 6.1 Phase 0：可信数据底座

- 稳定内部主键与数据格式版本。
- 全量迁移、验证、备份和回滚。
- 回收站和档案生命周期。
- 串行写队列、重复检测和写入失败恢复。
- API 鉴权、受限外部入口、请求限制和安全日志。
- API、迁移、并发和安全回归测试。

### 6.2 Phase 1：核心体验升级

- 收件箱、可自定义分类和标签。
- 研究模板系统。
- 全文和档案搜索。
- 首次使用向导、统一文案、错误提示和数据管理界面。
- 导入、导出、完整备份和恢复。
- 响应式、键盘操作和无障碍完善。

### 6.3 Phase 2：采集与分发

- Windows 一键启动或安装包。
- 保留源码/npm 启动作为跨平台高级入口。
- Bookmarklet；条件允许时提供浏览器扩展。
- 只读在线 Demo、演示视频、隐私说明和故障排查文档。
- Beta 反馈入口、诊断包和发布检查流程。

### 6.4 暂不纳入本轮

- 多人协作、账号体系和权限管理。
- 官方云同步和云数据库。
- 商业计费。
- 强制遥测。
- 大规模自动爬虫或定时批量抓取。
- 依赖云端服务的强制 AI 总结。
- 为增加数量而继续扩张企业 IM 平台。

## 7. 技术约束

### 7.1 架构

- 保留本地单机与 Markdown 可读数据的核心定位。
- `server.js` 继续只承担路由和编排，业务逻辑下沉到 `lib/`。
- 不为了本轮升级引入完整前端框架或云服务。
- 新数据格式必须提供显式版本和迁移器。

### 7.2 性能

- 1000 条数据下首屏可交互时间目标 ≤ 2 秒（不含外部抓取）。
- 本地搜索响应目标 ≤ 200 毫秒。
- 普通本地写入目标 ≤ 300 毫秒。
- 静态正文抓取目标 ≤ 8 秒，超时后可取消并明确降级。

### 7.3 安全与隐私

- 默认只监听 `127.0.0.1`。
- 所有非本机访问采用拒绝优先策略。
- 凭据不得写入仓库、数据文件、诊断包或普通日志。
- 外部 URL 和重定向链继续执行 SSRF 校验。
- 所有上传、导入和恢复操作必须限制大小并验证格式。

### 7.4 兼容性

- Windows 为 Beta 首要验证平台。
- Node.js 源码方式继续支持 macOS/Linux，但安装体验不作为首批硬门禁。
- 现有 `DATA.md` 和 `docs/entries/` 必须完整迁移。

## 8. 风险评估

| 风险 | 概率 | 影响 | 缓解方案 |
| --- | --- | --- | --- |
| 主键迁移导致条目与档案错配 | 中 | 高 | 只读扫描、迁移预览、完整备份、双重校验和回滚 |
| 安全改造破坏企业微信/钉钉入口 | 中 | 高 | 外部入口契约测试，回调权限与普通 API 分离 |
| 功能升级继续扩大产品边界 | 高 | 中 | 以核心研究闭环和本 PRD 范围为门禁 |
| Windows 打包带来维护成本 | 中 | 中 | 先做可靠的一键启动，再评估完整桌面封装 |
| Markdown 结构越来越复杂 | 高 | 中 | 数据格式版本、统一解析层和迁移测试夹具 |
| 公开 Beta 缺乏真实使用数据 | 中 | 中 | 小规模招募、任务制测试和主动反馈入口 |

## 9. 发布定义

满足以下条件才能发布 `2.0.0-beta.1`：

1. Phase 0 全部验收通过，没有已知阻断级数据与安全缺陷。
2. 首次收藏、重复处理、研究记录、归档、恢复五条主路径有自动化回归。
3. 旧数据迁移在真实副本和测试夹具上验证成功，并可回滚。
4. Windows 干净环境完成安装与首次收藏验证。
5. README、隐私说明、安全说明和实际行为一致。
6. 当前工作区中的钉钉能力完成测试并标为 Beta，或在发布包中明确禁用。

## 10. 依赖与决策

- 产品形态：本地单机。
- 主要用户：技术研究者。
- 发布目标：公开 Beta。
- 首发平台：Windows 优先。
- 数据政策：完整迁移、可回滚。
- 首要成功标准：激活与可靠性。

所有新增范围若改变以上六项决策，应先更新本 PRD 和实施计划。
