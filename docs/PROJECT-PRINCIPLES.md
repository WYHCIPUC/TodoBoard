# 灵感工作台项目原则

**状态**：生效中<br>
**版本**：0.1<br>
**最近复核**：2026-08-14

本文是产品、设计、工程、文档和发布决策的长期依据。版本计划说明“这一版做什么”，本原则说明“这个项目为什么这样做、发生冲突时优先保护什么”。

## 核心思想

> 先保全，再理解：把易失效、易遗忘的外部线索，转化为用户真正拥有、可以持续研究、能够追溯依据并推动行动的本地知识资产。

灵感工作台不是普通书签或待办清单。它要完成一条可闭环的路径：

```text
发现 → 保存 → 主动留存 → 研究 → 关联 → 验证 → 回顾
```

北极星不是“收藏了多少”，而是“有多少线索在来源失效后仍可访问，并最终形成了笔记、结论、方案或下一步行动”。

这里的阶段含义固定如下：**主动留存**是把能够取得的外部内容写入本地归档；**研究**是补充判断与行动；**关联**是从多个条目形成有证据的方案；**验证**是记录方案在真实实践中的结果；**回顾**是让旧条目和结论在合适时间重新进入视野。计划中的简写可以省略阶段，但不能改变这个顺序。

## 决策优先级

出现取舍时，按以下顺序决策：

1. 用户数据完整性与隐私安全。
2. 失败是否诚实可见、是否能够恢复。
3. 收藏—研究—决策主流程是否更顺畅。
4. 可访问性、性能与长期可维护性。
5. 视觉精致度与新功能数量。

高优先级不能为了低优先级让步。任何“更智能”或“更方便”的能力，都不能以静默丢失、强制上传或不可解释为代价。

## 九项原则

以下“验收标准”是长期应满足的行为，不等于当前版本已经全部实现；实际完成度以 [原则对照与补强计划](plans/2026-08-14-principles-gap-analysis.md) 为准。

### 1. 数据归用户，默认留在本机

- **含义**：核心数据使用人可读、可复制、可备份的本地格式；不依赖账号、订阅或专有云数据库才能使用。
- **验收标准**：`DATA.md`、研究档案和已保存方案可直接阅读；数据位置必须清楚。当前备份包覆盖主数据与条目档案，并应明确容量和未包含范围；单文件 EXE 实现程序与数据分离，源码/便携模式的同目录数据边界必须如实说明。
- **反例**：只存在浏览器内部或厂商云端、无法完整导出的内容。
- **决策问题**：停止维护应用后，用户是否仍能找到、理解并迁走自己的资料？

### 2. 先保存线索，再异步增强

- **含义**：URL 和用户已输入的信息先可靠落盘，解析、分类和归档随后进行。
- **验收标准**：网络失败或归档队列异常不会撤销已经保存的条目；自动分类只是建议。
- **反例**：等待外部解析完成后才允许收藏，或因抓取失败丢弃 URL。
- **决策问题**：最坏网络条件下，用户刚刚发现的线索还在吗？

### 3. 主动留存，安全降级

- **含义**：保存后尽快留存已经能够取得的正文、元数据、图片和原始页面；不同站点失败时逐级降级，并提供重试和人工补录。
- **验收标准**：归档具有 `queued`、`partial`、`failed`、`manual_required` 等明确状态；重试先经过质量比较，不能让低质量新结果覆盖最近有效内容。
- **反例**：承诺“链接永不失效”，或把只保存 URL 描述为完整备份。
- **决策问题**：来源明天删除时，今天成功取得的主要内容是否仍然存在？

### 4. 收藏是起点，研究与行动才是终点

- **含义**：每条收藏都应有机会进入“为什么保存—关键发现—行动项—结论—回顾”的生命周期。
- **验收标准**：内容支持研究模板、正文、笔记、截图、状态和计时；产品应能浮出未研究、归档失败或久未回顾的事项。
- **反例**：只优化采集数量，却没有再次发现、研究和形成结论的路径。
- **决策问题**：这项功能是在扩大收藏坟场，还是在提高形成成果的概率？

### 5. 结论带出处，方案能够验证

- **含义**：关联和建议必须展示原始条目、命中信号、置信度、证据缺口与最小验证步骤；最终判断属于用户。
- **验收标准**：头脑风暴结果可以回到来源档案，证据不足时明确提示补充信息，不强行生成结论。
- **反例**：用流畅文案掩盖弱证据，或把本地启发式分析包装成通用 AI 判断。
- **决策问题**：用户能否回答“为什么得到这个建议，以及怎样证明它有用”？

### 6. 修改可验证，破坏默认可逆

- **含义**：写入、迁移、导入、删除和升级都应有校验、备份、回滚或回收路径。
- **验收标准**：串行写入、原子替换、稳定 UID、迁移备份、回收站和可恢复队列共同保护数据。
- **反例**：半写入后继续报告成功，或在没有最后有效副本时覆盖原数据。
- **决策问题**：在写入中断、磁盘异常或用户误操作后，最近有效版本在哪里？

### 7. 默认最小暴露，外部入口权限最窄

- **含义**：默认只信任本机；抓取地址、上传文件和远程采集均采用拒绝优先与最小权限。
- **验收标准**：回环监听、会话鉴权、同源保护、限流、SSRF 校验；企业微信/钉钉入口只能完成受限采集。
- **反例**：为了手机收集而把完整数据 API 暴露到公网，或把 Cookie、Token 写入日志和备份。
- **决策问题**：这个入口是否拥有超过完成单一任务所需的能力？

### 8. 用户入口要简单，内部复杂度要受控

- **含义**：普通用户应能一键启动、无需 API Key 完成核心流程；工程内部保持模块边界和克制依赖。
- **验收标准**：普通用户有无需 Node.js 的 Windows 成品；单文件 EXE 与数据分离；`server.js` 负责路由编排，业务逻辑进入 `lib/`；非必要不引入框架和云依赖。
- **反例**：把环境变量、命令行或第三方账号变成基础使用前提，或把所有前端职责继续堆进单一文件。
- **决策问题**：这项复杂度是用户核心价值所必需，还是维护者可以避免的负担？

### 9. 范围克制，小步演进，结果可证

- **含义**：优先补强可靠性、回顾和研究闭环，再扩张平台数量；每次变化都要有可验证、可回滚的交付物。
- **验收标准**：功能先写计划和失败边界，Bug 先补复现测试，发布执行数据、安全、浏览器和 Windows 门禁。
- **反例**：以接入平台数、生成内容量或界面模块数代替真实用户价值。
- **决策问题**：如果只能做一件事，它是否比修复当前闭环中最弱的一环更重要？

## 产品边界

当前明确不把以下内容作为核心能力：

- 强制账号、官方云同步、多人协作和团队权限。
- 强制外部 AI、必须自备 API Key 的基础功能。
- 大规模定时爬虫或“支持所有网站”的承诺。
- 未经官方支持的微信传输助手自动化；移动采集应使用权限受限、可维护的正式入口。
- 默认遥测、以使用时长为目标的信息流或成瘾机制。
- 设备绑定、强制联网验证或破坏本地数据所有权的授权限制。商业价值来自可靠成品、交付与服务，而不是锁住用户数据。

本地优先不等于完全离线：网页抓取和可选消息入口会访问第三方网络。产品必须准确说明哪些数据出站、哪些只留在本机。

可选外部 AI 未来可以作为显式启用的适配器，但核心流程必须在未配置 AI 时完整可用；启用前要展示将发送的字段、服务方和保存方式，生成结果仍需保留来源与人工确认。

当前本地文件和导出包不提供应用层加密，安全前提是可信本机账户，并建议使用操作系统磁盘加密。应用应提示明文导出的风险，不自行设计难以恢复的加密协议。归档也不得绕过登录、付费或访问控制；用户负责确认个人留存内容的授权与使用边界。

## 网络与数据边界

| 能力 | 可能经过的第三方 | 发送或暴露的内容 | 本地结果 |
| --- | --- | --- | --- |
| 本地浏览、研究、头脑风暴 | 无 | 无 | 读取 `DATA.md`、档案和本地方案 |
| 网页解析与归档 | 目标站点；如显式配置则包括代理服务 | 目标 URL、常规网络请求信息；X Cookie 仅可发送给 X/Twitter 域名 | URL、元数据和成功取得的归档内容 |
| 企业微信采集 | 企业微信与用户配置的 HTTPS 转发链路 | 用户发送的消息和链接、回调鉴权数据 | 受限入口仅新增链接并记录来源 |
| 钉钉采集 | 钉钉 Stream 服务 | 用户发送的消息和链接、SDK 鉴权数据 | 受限入口仅新增链接并记录来源 |
| 在线 Demo | GitHub Pages 等静态托管 | 只读取公共示例文件，不发送个人数据 | 只读示例，不写本地数据文件 |

具体配置和风险见 [安全策略](../SECURITY.md)、[企业微信指南](WECOM-GUIDE.md) 与 [钉钉指南](DINGTALK-GUIDE.md)。

## 新需求决策检查表

任何功能或重大重构至少回答：

1. 它改善工作流的哪个阶段，预期用户结果是什么？
2. 不联网、站点失效或第三方限流时如何降级？
3. 会读取、写入、上传或导出哪些用户数据？
4. 失败是否会影响已经保存的 URL、正文、笔记或附件？
5. 如何撤销、恢复或迁移？
6. 结论如何追溯，自动化如何由用户确认？
7. 是否增加强制账号、API Key、运行依赖或维护面？
8. 需要哪些单元、集成、浏览器和分发验证？

如果答案不清楚，先更新设计文档，不进入实现。

## 质量与发布底线

- 不发布已知阻断级数据丢失或未授权访问问题。
- 文档只陈述已经验证的能力；目标指标必须标为目标，不能冒充事实。
- 自动化检查、真实浏览器主流程和 Windows 成品验收按改动风险执行。
- 发布包不得包含 `DATA.md`、研究档案、日志、队列、凭据或用户备份。
- 外部抓取成功率会随站点变化；必须保留固定夹具、联网冒烟记录和人工兜底。

“主数据与条目档案备份”指 `DATA.md` 及备份清单允许的条目文件，不自动包含头脑风暴目录、运行队列、回收站和日志。“本地归档完整性巡检”只证明已记录文件存在、可读且校验一致，不代表来源页面仍在线、内容最新或与外站完全一致。

## 术语

- **灵感工作台**：产品名称。
- **灵感来袭**：收集与研究工作区。
- **头脑风暴**：关联与决策工作区。
- **LingganKanban**：包名、数据目录等内部兼容标识。
- **TodoBoard**：GitHub 仓库的历史标识，不作为产品对外名称。

## 修订规则

原则保持稳定，但不是不可修改。若新决策需要违反原则，应在 `docs/plans/` 中记录原因、影响、替代方案、退出路径和验证结果。每个稳定版本发布前复核一次原则与现状对照；阶段性完成状态写入计划，不写进本文件。

当前对照与补强顺序见 [原则对照与补强计划](plans/2026-08-14-principles-gap-analysis.md)。历史定位与阶段目标见 [公开 Beta PRD](product-upgrade-prd.md)。
