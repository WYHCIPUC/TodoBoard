# v2.2.0：可信恢复与确定性 Windows 发布

发布日期目标：2026-08-27。当前状态：本地候选、Windows 成品和介绍视频已准备完成，待远端认证、仓库规则、tag 与 GitHub Release 门禁；在这些门禁完成前不代表已经公开发布。

## 兼容性与资产

- 源码：Node.js 22 或 24；`package.json` 要求 `>=22`，Node.js 20 不受支持。
- Windows 成品：Windows 10/11 x64，内置 Node.js 24.16.0。
- 资产名：`linggankanban-2.2.0-windows.zip`、`linggankanban-2.2.0-windows-portable-x64.zip`、`linggankanban-2.2.0-windows-x64.exe`、两个同名 `.manifest.json`、严格命名的 `SHA256SUMS.txt`，以及产品片 `linggan-v2.2-promo.mp4` / `linggan-v2.2-promo-no-bgm.mp4`。
- EXE 可能未做商业代码签名；必须从可信 Release 下载并核对 SHA-256。

## 主要变化

v2.2 把所有关键写入、升级和恢复放到同卷锁定事务中：写入临时副本、同步、验证、轮换已验证备份、原子替换并写后复验。恢复先展示状态和候选证据；证据歧义时停止，用户显式选择并确认后才变更。恢复和升级使用稳定操作 ID、持久状态和收据，重跑不会重复提交。

归档内容、质量判断与完整性证据分离保存。网络失败会成为可见、可重试状态，不会撤销已保存链接或静默删除已有正文。

发布构建只复制 `scripts/release-allowlist.txt` 中的普通文件，固定 `scripts/runtime-node.json` 中的 Node 24 ZIP 与 `node.exe` 哈希，拒绝链接、路径穿越、额外文件和敏感模式。ZIP 排序并固定时间戳；两次干净构建必须逐字节一致。

## 升级与数据位置

升级前停止旧服务并复制整个数据目录。单文件 EXE 默认数据根为 `%USERPROFILE%\Documents\LingganKanban`；便携/源码版默认与应用同目录，环境变量配置优先。

v1/v2.1 迁移副本位于 `.linggan/migration-backups/`；v2.2 升级快照位于 `.linggan/upgrade-snapshots/pre-2.2.0-*`。启动器在快照、迁移和验证完成前不会开放数据 API。中断后再次启动会从持久状态收敛；不明确或不可验证的状态要求人工恢复。

## 恢复、回滚与已知失败

只读检查：

```powershell
node scripts/recover.js --help
node scripts/recover.js --json
```

先停止其他实例并在数据目录副本上检查。`ambiguous_recovery` 表示没有唯一可信候选；`data_in_use` 或 `legacy_instance_may_be_running` 表示不能证明写入安全；`manual_recovery_required` 表示事务或验证无法自动收敛。以上情况都不得删除锁、猜测候选或直接覆盖 `DATA.md`。

确认恢复必须使用 CLI/UI 当次预览给出的事务和候选，显式 `--apply` 并交互确认。变更前创建已验证副本，变更后复验并写入收据。升级回滚仅接受 manifest SHA-256 匹配且标记为 restorable 的升级前快照；回滚前还要保存当前失败状态副本。

当前限制：仅提供 Windows x64 成品；本地文件和导出包不做应用层加密；无云同步或多人协作；外部网页解析受网络、登录、限流和页面变化影响；应用不会绕过登录或付费访问控制。
